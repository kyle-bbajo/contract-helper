## 1. 설치 자세히

아무것도 깔리지 않은 PC에서도 아래 한 가지로 끝까지 설치·실행됩니다. 이미 설치된 것은 건너뜁니다.

| PC | 처음 한 번 | 실행 |
|---|---|---|
| 맥 | `bash setup.sh` | `NOW=12:00 bash run.sh` (서버가 뜨면 브라우저에 표지가 자동으로 열림) |
| 윈도우 | `run.bat` 더블클릭 (설치와 실행을 한 번에) | 다시 `run.bat` 더블클릭 (브라우저 자동으로 열림) |
| 리눅스 · WSL | `bash setup.sh` | `NOW=12:00 bash run.sh` 후 브라우저에서 http://localhost:8000 |

**맥 `setup.sh`** 는 없는 것만 차례로 설치합니다: Homebrew(맥 비밀번호·Enter를 물음) → Python 3.12 → 패키지 → 가상 데이터 → MySQL 가상 DB → Ollama · gemma3:4b(약 3GB). 처음에는 10~20분 걸립니다.
- `mysql` 명령만 있고 서버가 없는 맥도 MySQL 서버를 설치합니다. `brew services`가 권한 문제(`~/Library/LaunchAgents`)로 막히면 `mysql.server`로 직접 켭니다.
- MySQL을 설치·실행하지 못하면 `data/input`의 CSV로 바꿔 끝까지 진행합니다(기능은 같음). Ollama나 모델을 받지 못해도 문장 모델 없이 나머지는 모두 동작합니다.

**리눅스 · WSL `setup.sh`** 는 Python·venv·curl·MySQL이 없으면 apt로 설치합니다(sudo 비밀번호를 물을 수 있음).

**윈도우 `run.bat`** 은 Python 3.10 이상이 없으면 설치하고(winget, 안 되면 python.org), 폴더 안 전용 환경(`.venv`)에 패키지를 깔고, 서버가 뜨면 기본 브라우저로 표지를 엽니다.
- 다른 Python·아나콘다가 있어도 3.13 → 3.10 순으로 맞는 버전을 골라 `.venv`만 씁니다. 다른 PC에서 복사해 온 `.venv`가 깨져 있으면 다시 만듭니다.
- 8000번 포트를 다른 프로그램이 쓰면 8001, 8002… 빈 포트로 엽니다(창에 주소가 나옴).
- Ollama가 없으면 설치하고(winget, 안 되면 ollama.com 설치 파일), `gemma3:4b`(약 3GB)는 별도 창에서 받습니다. 앱은 기다리지 않고 바로 열리며, 받기가 끝나면 식단 사진 인식·안내 문장이 켜집니다. 건너뛰려면 `set NO_LLM=1` 뒤 실행.
- MySQL 없이 CSV로 돌고, 기준 시각은 12:00입니다.

| 선택 (맥 · 리눅스) | 방법 |
|---|---|
| MySQL 없이 | `DB=csv bash setup.sh` |
| 문장 모델 없이 | `NO_LLM=1 bash setup.sh` |
| 더 큰 모델 (GPU) | `MODEL=gemma3:12b bash setup.sh` |
| 가상 DB 다시 만들기 | `REBUILD_DB=1 bash setup.sh` |
| 다른 기기에서 | `.env`에 `HOST=0.0.0.0`, `ADMIN_PASSWORD=` |

## 2. 동작 방식

누구에게 연락할지는 규칙이 정하고, AI는 규칙으로 안 되는 일만 맡습니다. AI가 없거나 실패하면 규칙으로 동작합니다.

| 일 | 방법 |
|---|---|
| 평소 오는 시간, 연속 미출석, 연락 단계 | 규칙 (출석 기록 통계) |
| 미출석을 몇 시에 알릴지 | 머신러닝: 그래디언트 부스팅 |
| 30일 뒤 체지방률 | 생리학 공식 + 검증될 때만 릿지 회귀 보정 |
| 안내 문장, 회원 글 이해, 음식 사진, 시간표 이미지 | 문장 모델 gemma3 (Ollama, 기관 PC 안) |

### 2.1 평소 오는 시간

| 항목 | 기준 |
|---|---|
| 보는 기간 | 최근 26주 출석 |
| 평소 요일 | 요일·강좌마다 올 수 있었던 날(휴관·휴강·휴회·수강 기간 밖 제외)의 50% 이상, 3번 이상 온 요일 |
| 평소 시각 | 최근 12번 도착 시각의 중앙값 (오는 시간을 바꾸면 따라감) |
| 기다리는 시간 | 도착 시각이 흩어진 정도(중앙값과의 차이 80% 지점), 30\~60분 |

### 2.2 미출석 판정과 연락 단계

| 단계 | 조건 | 받는 사람 |
|---|---|---|
| 회원 화면 알림 | 평소 시각 + 기다리는 시간(모델을 쓰면 모델이 정한 시각)이 지나도 그날 출석 없음 | 회원 화면 (알림을 켠 휴대폰은 웹 푸시) |
| 본인 안부 문자·알림톡 | 평소 오던 날 2번 연속 미출석, 또는 출석 없이 7일 | 회원 |
| 보호자 안부 문자·알림톡 | 3번 연속, 또는 14일. 폭염(최고 33℃ 이상)·한파(최저 -12℃ 이하) 예보일엔 2번 또는 10일 | 동의한 보호자 |
| 주민센터 전달 | 보호자가 없거나 보호자가 확인하지 않음 | 직원 → 엑셀 |

- 휴회·휴관·수강 기간 밖은 세지 않습니다. 그날 다른 강좌로라도 오면 출석입니다.
- 휴회가 끝난 뒤에도 평소 오던 날에 안 오면 그날부터 다시 셉니다.
- 보호자나 직원이 확인하면 꺼지고, 그 뒤 3번(또는 14일) 더 안 오면 다시 알립니다.
- 보호자 출석 보기는 보호자가 수신에 동의하고 회원이 허락한 경우에만 열립니다. 보호자 등록 화면에서 기본으로 켜져 있고, 회원 화면 알림 탭에서 보호자별로 끄고 켭니다.

연락이 닿는 길은 문자 또는 카카오 알림톡입니다. 회원 화면은 휴대폰 브라우저로 여는 웹페이지라, 화면 알림은 회원이 화면을 열었을 때 보이고 "알림 켜기"를 누른 휴대폰에만 웹 푸시로 뜹니다. 화면을 열지 않는 어르신도 있으므로 안부 연락은 화면 알림에 기대지 않고 문자·알림톡으로 보냅니다.

| 길 | 언제 쓰나 | 비용 |
|---|---|---|
| 카카오 알림톡 | 설정에서 알림톡을 고르고 기관 카카오 채널과 카카오가 승인한 템플릿이 있을 때. 못 받으면(카톡 없음 등) 같은 내용을 문자로 다시 보냄 | 건당 |
| 문자 (SMS·LMS) | 기본. 알림톡을 쓰지 않거나 대체 발송일 때 | 건당 |
| 웹 푸시 | 회원 화면 알림을 휴대폰에 띄울 때만 (회원이 켠 경우) | 없음 |

문자·알림톡은 솔라피 API로 보내고, 같은 일로 두 번 보내지 않도록 보내기 전에 기록부터 남깁니다.

### 2.3 출석 예측 모델

| 항목 | 내용 |
|---|---|
| 학습 자료 | 회원이 올 수 있었던 날 하루 = 한 줄, 최근 104주 (30만 줄 넘으면 무작위 추출) |
| 모델 | scikit-learn HistGradientBoosting 두 개: 올 확률(분류), 도착 시각의 90% 지점(분위 회귀) |
| 알림 시각 | 평소 시각 + 90% 지점 + 여유(검증으로 0\~30분 중 선택), 20분\~6시간 사이 |
| 특징 | 17개 (아래) |
| 누수 방지 | 모든 특징은 판정 시각에 알 수 있는 것만: 그날 이전 기록, 평소 시각 기준 날씨, 그 시각까지의 시설 흐름 |
| 평가 | 시간 순서로 나눔: 마지막 28일 = 시험, 그 앞 28일 = 여유 선택, 나머지 = 학습 |
| 채택 조건 | 시험 기간에 규칙보다 놓친 결석·헛알림·알림 시각이 모두 같거나 낫고, 하나는 나을 때만 사용. 아니면 규칙 |
| 다시 학습 | 앱 시작, 회원·수강·휴회가 바뀔 때, 하루 한 번 어제 실제 날씨가 들어올 때 |

#### 특징 17개

- 출석 습관 5: 요일 출석률, 요일 출석 횟수, 강좌 출석률, 연속 결석, 마지막 출석 후 날수
- 시각 2: 평소 시각, 흩어짐
- 달력·회원 3: 요일, 월, 나이
- 날씨 6: 최저·최고기온, 하루 강수·적설, 평소 시각 전 3시간 강수, 평소 시각 기온
- 시설 흐름 1: 그날 평소 시각까지 온 회원 수 ÷ 지난 같은 요일 4번 평균 (본인 제외)

결석한 날은 규칙이든 모델이든 반드시 알립니다. 모델은 언제 알릴지만 정합니다.

#### 모델을 고른 이유

| 후보 | 판단 |
|---|---|
| 그래디언트 부스팅 (채택) | 표 자료의 가장 강한 기본값. 수백만 줄도 CPU로 몇 분, 판단에 쓴 특징을 보여 줌 |
| TabPFN (표 자료용 트랜스포머) | 수만 줄 이하에선 더 나을 수 있으나 그 이상은 못 다루고 GPU 필요. 비교 후보 |
| FT-Transformer 등 표 자료 딥러닝 | 비교 연구에서 부스팅과 비슷하거나 못하고, 학습이 무겁고 설명이 어려움 |
| 시계열 모델 (TimesFM, Chronos 등) | 수치를 예측하는 모델이라 "오늘 올까, 몇 시에 올까"와 맞지 않음 |

어떤 모델을 넣든 같은 조건(시간 순서 평가, 규칙보다 나을 때만 사용)으로 고릅니다.

#### 가상 회원 2만 명·10년치 실험 (출석 423만 건)

| 항목 | 결과 |
|---|---|
| 학습 시간 | 1분 52초 (일반 PC, CPU 2개·메모리 8GB) |
| 미출석 알림 누락 | 0건 / 7,434건 |
| 헛알림 (알렸는데 늦게라도 온 날) | 규칙보다 25\~32% 적음 |
| 알림 시각 | 평소 시각 + 26\~28분 |
| 올지 맞히는 정도 (AUC) | 0.677 (그 요일 출석률만 쓰면 0.637) |

미출석 알림을 놓치지 않았다는 뜻이지 고독사 감지율은 아닙니다. 가상 데이터의 날씨 효과는 생성기에 넣은 가정이라 실제 효과는 기관 자료로 다시 학습해야 압니다.

### 2.4 30일 뒤 체지방률

| 항목 | 내용 |
|---|---|
| 운동 1회 열량 | MET × 3.5 × 체중(kg) ÷ 200 × 운동 시간(분). 강좌별 MET·시간은 `config.json` |
| 지방 변화 | (한 달 출석 × 1회 열량 + 식단 조절 시 하루 300kcal × 30일) ÷ 7,700kcal/kg |
| 근육량 변화 | 출석률에 따라 한 달 -0.1 \~ +0.3kg |
| 4가지 경우 | 지금처럼 / 식단 조절 / 주 1회 더 / 둘 다 |
| 학습 보정 | 공식과 실제 변화의 차이를 릿지 회귀로 학습. 교차검증에서 오차가 2% 이상 줄 때만 사용 |
| 안전 범위 | 한 달 변화 -2.0 \~ +1.5%p로 제한 |

학습 보정은 측정이 2회 이상인 회원으로 하고, 월 출석·체지방률·나이·성별·근육 비율·유산소와 근력 비중을 씁니다. 교차검증은 회원 단위 5겹입니다.

### 2.5 문장 모델

| 쓰는 곳 | 실패하면 |
|---|---|
| 안내 문자 다듬기 (독려·재등록 등) | 정해진 문장 |
| 회원 글 → 건강 항목 ("무릎이 시큰해요" → 무릎·고관절) | 키워드 일치 |
| 음식 사진 → 음식·열량, 시간표 이미지 → 강좌·요일·시간 | 직접 입력 |

안부 문자(본인·보호자)와 동의 요청은 모델을 쓰지 않고 정해진 문장으로만 나갑니다. 모델 출력에서 문자에 못 쓰는 기호는 지웁니다.

## 3. 외부 연결

### 3.1 공공 API

| API | 쓰는 곳 | 키 |
|---|---|---|
| 기상청 단기예보 (공공데이터포털) | 오늘 날씨 → 미출석 판정 | `KMA_SERVICE_KEY` |
| 기상청 ASOS 시간자료 (공공데이터포털) | 과거 날씨 → 출석 예측 학습 | 같은 키 |
| 한국천문연구원 특일 정보 (공공데이터포털) | 공휴일 → 미출석에서 제외 | 같은 키 |
| 행정안전부 도로명주소 (business.juso.go.kr) | 시설 주소 | `JUSO_SEARCH_KEY` |
| 국토교통부 브이월드 (vworld.kr) | 시설 좌표 → 날씨 격자, 지도 | `VWORLD_KEY` |

시설 주소를 입력하면 가장 가까운 기상청 관측소의 과거 날씨를 받아 `data/output/weather_history.csv`에 따로 저장하고(출석 원본은 읽기만 합니다), 학습할 때 출석 날짜·시각에 맞춰 붙입니다. 위치를 바꿔 관측소가 달라지면 이전 지역 자료를 버리고 새 지역 자료를 처음부터 받습니다.

연결 순서: 시설 주소(도로명주소) → 좌표(브이월드) → 기상청 5km 격자(LCC 좌표 변환) → 그 격자의 오늘 날씨를 30분마다, 가장 가까운 ASOS 관측소의 과거 시간자료 104주를 한 번 받고 빠진 날만 추가. 공휴일은 하루 한 번 학습 기간 첫 해부터 내년까지 받습니다.

모두 무료이고 실제 발급 키로 확인했습니다. 밖으로 나가는 것은 시설 좌표·주소뿐입니다. 키는 `.env`(`.env.example` 참고)나 관리자 설정 화면에 넣고, 신청 방법은 운영안내 "외부 API 연결".

키가 없어도 실행됩니다. 날씨는 `data/input/weather.csv`, 공휴일은 `holidays` 패키지로 대신하고, 주소 검색과 문자 발송은 꺼집니다.

### 3.2 그 밖의 연결

| 연결 | 쓰는 곳 | 키 |
|---|---|---|
| 솔라피 (민간, 건당 요금) | 안부·안내 문자와 카카오 알림톡 (운영은 기관 계약 사업자로) | `SOLAPI_API_KEY` `SOLAPI_API_SECRET` |
| 웹 푸시 (Web Push 표준, 무료) | 회원 화면 알림을 브라우저가 닫혀 있어도 휴대폰에 | 없음 (서버 키는 처음 실행 때 자동 생성) |
| Ollama (기관 PC) | 문장·사진 | `LLM_MODEL` |
| 회원관리 프로그램 DB | 회원·출석 (조회만) | `MEMBER_DB` |
| 인바디 DB · .mdb | 체성분·혈압 | `INBODY_DB` |
| 나의건강기록 · 국민비서 | 검진 · 공공 알림 (기관 승인 뒤) | — |

### 3.3 문장 모델 연결

기본은 Ollama + `gemma3:4b`입니다. 앱과 같은 PC에서 CPU로 동작하고, 없거나 꺼져 있으면 규칙 문장으로 대신합니다. 관리자 설정 → 문장 모델에서 고르면 바로 바뀌고(`data/output/settings.json`에 저장), `.env`로도 정합니다.

| 항목 | `.env` | 값 |
|---|---|---|
| 연결 방식 | `LLM_PROVIDER` | `ollama` · `openai_compatible` (vLLM, 외부 API) · `none` (규칙 문장만) |
| 모델 | `LLM_MODEL` | `ollama pull`로 받은 모델: `gemma3:4b`, `gemma3:12b`, `exaone3.5:7.8b` 등 |
| 주소 | `LLM_BASE_URL` | `http://localhost:11434` |
| 키 | `LLM_API_KEY` | 외부 API일 때만 |

#### 두 모델 비교

같은 입력으로 시험했습니다 (설정 → 현재 모델 시험하기, 그래픽카드 서버).

| 모델 | 안내 문자 | 회원 글 "계단 오를 때 무릎이 시큰하고 혈압약을 먹어요" |
|---|---|---|
| gemma3:12b | 1.0초 | 무릎·고관절, 고혈압 (둘 다 맞음) |
| exaone3.5:7.8b | 2.2초 (끝에 붙인 이모지는 코드에서 지움) | 무릎·고관절 (고혈압 놓침, 회원이 화면에서 체크) |

외부 API로 바꾸면 회원이 쓴 글과 리포트 수치가 그 서비스로 넘어갑니다.

## 4. 안전과 제약

### 4.1 잘못 알리지 않기 위해

| 상황 | 동작 |
|---|---|
| 회원관리 DB를 못 읽음 | 판정·자동 문자 멈춤, 읽히면 재개 |
| 문자 보내다 종료·응답 없음 | 다시 안 보내고 "확인 필요"로 남김 |
| 날씨·공휴일·문장 모델 실패 | 마지막 자료나 규칙으로 계속 |
| 측정값 없음·오류 | 있는 것만으로 리포트, 이상한 값은 뺌 |
| 오래 안 온 회원 | 수강 중이면 2주마다 다시 알림 |

### 4.2 알려진 제약

- 예측은 참고용이지 진단이 아닙니다. 기준값(`config.json`)은 운영 전 전문가 검토가 필요합니다.
- 회원 로그인(회원번호 + 출생년도)은 간이 확인입니다. 운영하려면 본인인증으로 바꾸고, 외부에 열 때는 가상 데이터·관리자 비밀번호·VPN 안에서만.
- DB 연결과 주민센터 전달(개인정보 제3자 제공)은 기관 개인정보 담당 승인 뒤에 합니다.
- 문자는 실제 발송까지 확인했습니다. 알림톡은 기관 채널이 없어 요청 형식만 시험했습니다. 웹 푸시는 암호화를 표준 시험 벡터로 검증했습니다.
- 휴대폰 알림(웹 푸시)은 https 주소에서만 동작합니다(아이폰은 홈 화면에 추가 후, iOS 16.4 이상). localhost·SSH 터널로 여는 시연 환경에서는 휴대폰 알림이 오지 않으며, 문자는 정상 발송됩니다.
- 시설 한 곳 기준입니다. 여러 곳이면 휴관일·날씨를 시설별로 나눠야 합니다.
- 사진으로 읽은 음식 열량은 오차가 큽니다.
- 문장 모델은 저장소에 없고 각 모델의 라이선스를 따릅니다. EXAONE 3.5는 비상업 라이선스입니다.

### 4.3 확산 방향

같은 구조로 넓힐 수 있는 범위입니다. 어린이 강좌 알림만 구현돼 있고(기본 꺼짐), 나머지는 연결 설정으로 적용합니다.

- 다른 공공체육시설: 같은 회원관리 프로그램을 쓰면 DB 연결 설정만 바꾸면 됩니다.
- 노인복지관·경로당: 회원·날짜·입장 시각만 있는 출석 기록이면 같은 방식으로 판단합니다.
- 어린이 강좌: 학원 출결 알림처럼 수업 시간이 지나도 오지 않으면 보호자에게 바로 알리는 기능을 넣어 두었습니다. 기본은 꺼져 있고 설정 → 기능에서 켜고 끕니다(운영안내 "어린이 강좌 출결 알림").

## 5. 저장소 정보

### 5.1 데이터

실제 회원 자료는 없습니다. 회원관리 프로그램·인바디의 실제 자료 구조와 유사한 구조로 가상 데이터를 생성해 사용했습니다. 실제 자료로 바꿀 때는 조회문의 표·칸 이름만 맞추면 됩니다. 회원 휴대폰 번호는 실제로 쓰지 않는 010-0 대역이라 문자가 나가지 않습니다. 기준일이 2026-10-26으로 고정되어 있어 언제 실행해도 그날 기준으로 동작합니다. 입력은 읽기만 하고 결과물은 `data/output/`에 씁니다.

| 자료 | 지금 | 운영 |
|---|---|---|
| 회원관리 프로그램 | MySQL `hr_facility` | 업체 DB 조회 전용 계정 |
| 인바디 | MySQL `hr_inbody` | LookinBody `.mdb` · DB |
| 건강검진 · 날씨 | `data/input/` CSV | 나의건강기록 · 기상청 |

### 5.3 대회 규칙

- 패키지: Flask, pandas, numpy, scikit-learn, holidays, cryptography (+ pymysql). CDN 없음.
- 모델 비종속: 문장 모델은 설정에서 바꾸고, 없어도 전부 동작합니다. Gemma 3·EXAONE 3.5 두 모델로 주요 기능 확인 (3.3 문장 모델 연결).
- 자료: 실제 자료와 유사한 구조로 생성한 가상 데이터만 있고, 실제 자료로 학습한 모델은 없습니다. `.env`, `*.mdb`, `data/output/`은 커밋되지 않습니다.
- 원본 보호: 입력 폴더와 DB는 읽기만 합니다.
- 보안: 바깥 요청은 http·https만, 로그인 뒤 돌아가는 주소는 이 사이트 안만, 학습 모델은 파일로 저장하지 않음(pickle 없음). 화면 그래프는 이미지로 넣음.
- 검증: 테스트 154개 (DB → 판정 → 문자 흐름, 재시작·반복 점검 포함). 새 Ubuntu 24.04에서 설치부터 화면까지 확인. Python 3.13 · flask 3.1.3 · pandas 3.0.5 · numpy 2.5.3 · scikit-learn 1.9.1
